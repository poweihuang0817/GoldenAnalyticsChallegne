THE APPLICATION CONTRACT
Build expressions. Execute when ready.
Typed predicates and named projections, with no callback API.


1. Start from a schema
const source = createSource(challengeCatalog);
const customers = source.table('customers');
The catalog supplies field names, logical types and nullability. Construction opens no database connection.
2. Describe the computation

Columns are expressions, not row values. Filter keeps TRUE rows; aggregate produces a new relation. Use the new table's columns in each following stage.


3. Pick an execution target
const client = createClient('duckdb', challengeCatalog);
try {
  const query = cityQuery('london');
  const { rows } = await client.execute(query);
  console.log(rows);
} finally {
  await client.destroy();
}
The same query can execute on postgres, mysql or duckdb. Execution compiles the plan and sends SQL to the selected backend.
4. Inspect when useful
const preview = client.compile(query);
// preview.sql + preview.parameters
const plan = query.toSubstrait();
Call compile while the client is open. Preview does not execute SQL; parameter values may be sensitive.


Checks before execution
Known columns, compatible expression types and inferred output fields. A left join makes right-side outputs nullable. Runtime checks still protect relation scopes and unsupported operations.
Composable relations
Average units per order is SUM per order ? left join orders ? AVG. The compiler inserts the required SQL subqueries.
Honest result types
Decimal and i64 values stay strings. Computed MySQL i32 values can also be strings; the inferred result type reflects that.

THE TRANSLATION BOUNDARY
Intent stays portable. Execution stays with the backend.



Public API
Table / Expr describes WHAT to compute. Immutable stages expose their own typed output schema.
Relational contract
Substrait is the supported IR, not the user interface. Validation rejects unsupported features; lowering preserves joins, ordering and aggregate grain.
Execution
Kysely constructs parameterized SQL. PostgreSQL/MySQL run remotely; DuckDB runs against a separately seeded local snapshot. No federation.


Future work: capability handling, authentication options and normalized errors. Semantic frontends and federation are not implemented.
