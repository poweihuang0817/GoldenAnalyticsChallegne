USING THE API
Build a query once. Choose where to run it.
A Northwind example: count customers in London using typed expressions.


1. Choose a table
const source = createSource(challengeCatalog);
const customers = source.table('customers');
The catalog describes table names, columns, types and nullable fields. A declared schema gives TypeScript autocomplete and catches unknown columns or incompatible operations. Creating a source or table does not fetch data.
2. Filter and aggregate
Loading the actual city query…
cityQuery('london') builds a query object. The filter compares lowercase city names; the aggregate names the output customer_count. These steps describe the work without running it.
The helper above is actual source from src/queries.ts. Imports and the shared source/catalog setup are omitted.


3. Execute on a backend
const query = cityQuery('london');
const client = createClient('postgres', challengeCatalog);

try {
  const { rows } = await client.execute(query);
  console.table(rows);
} finally {
  await client.destroy();
}
execute() compiles and runs the query asynchronously. It returns an object containing rows. Close the client after all queries finish to release its connections.
Use 'mysql' with the same query. For 'duckdb', seed the local Northwind snapshot first.
Optional: preview SQL
const preview = client.compile(query);
console.log(preview.sql);
Use this inside the try block before execute(). Compilation is synchronous and does not run the data query. It is useful for debugging; normal execution does not require a separate compile step.


Typed expressions
Columns support operations appropriate to their type. Predicate and projection objects compose without callbacks. Runtime checks also validate query scope and supported operations.
Queries can build on queries
For average units per order, first sum quantities per order, join those totals to orders, then average. Each transformation produces a new relation with its own output columns.
Reading results
The London example returns { customer_count: '6' }. Counts and decimal values are strings to avoid losing integer or decimal precision. Convert them only when your application can safely do so.
Other numeric results
Computed MySQL 32-bit integer values can also arrive as strings. The inferred result type allows this; the API does not promise every numeric column is a JavaScript number.

THE TRANSLATION BOUNDARY
Intent stays portable. Execution stays with the backend.



Public API
Table / Expr describes WHAT to compute. Immutable stages expose their own typed output schema.
Relational contract
Substrait is the supported IR, not the user interface. Validation rejects unsupported features; lowering preserves joins, ordering and aggregate grain.
Execution
Kysely constructs parameterized SQL. PostgreSQL/MySQL run remotely; DuckDB runs against a separately seeded local snapshot. No federation.


Future work: capability handling, authentication options and normalized errors. Semantic frontends and federation are not implemented.
